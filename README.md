# PGA-TapeStudio

PGAはテープの「ピーガー」音から。Windows用の、**保存済みのテープWAVを実機へ再生する機能と、LINE OUT → 抵抗入りケーブル → MIC IN の録音を検査する機能**を備えたツールです。

## 起動

`Start.cmd` をダブルクリックしてください。Windows付属の .NET Framework のコンパイラーでビルドして起動します。ビルド後は `bin\pga.exe` から直接起動できます。

音声の読み込みには **FFmpeg** が必要です。PATHにある `ffmpeg.exe`、または `bin\ffmpeg.exe` を使用します。このPCでは既存のFFmpegを使って動作確認しています。追加のPython・Node・NuGetパッケージは不要です。

## テープWAVの再生

1. 保存済みのWAVを「音声を選択」またはドラッグ＆ドロップで指定します。
2. 実機に接続した「再生出力」と出力ゲインを選びます。必要なら別のヘッドホン等を「モニター」に指定します。
3. 「再生のみ（1倍）」で開始します。**速度は100%固定**で、「測定速度」の設定は使いません。録音入力とDumpListEditorは不要です。
4. 「一時停止」「再開」「停止」を使えます。モニターの音量スライダー（0～100%、0はミュート）は再生中・一時停止中にも操作でき、測定用出力のゲインは変えません。

「全部」はファイル末尾まで、OFFなら指定秒数まで再生します。波形の「位置」は表示位置であり、再生位置を移動するシーク機能ではありません。再生のみでは録音・自動比較・認識検査を行いません。WAV化済みのダンプを対象とし、ダンプ形式からのWAV生成機能はありません。

### 実機での動作確認・既知の問題

ユーザーによる動作確認報告：

- 一部のタブレットPCでは、正常にテープデータを送出できない問題が発生しています。
- 多摩電子工業の **FFS16CK** 経由の接続では、実機で正常にロードできたことを確認しています。

問題が発生したPCの機種・接続条件と原因は未特定です。FFS16CK経由での成功は確認した構成での結果であり、すべてのタブレットPCでの動作確認ではありません。

## 測定

1. LINE OUT と MIC IN を抵抗入りケーブルで接続します。出力音量を小さくしておきます。
2. 録音入力に接続した MIC IN、再生出力に接続した LINE OUT を選びます。表示順の先頭が選ばれるため、**測定前に必ず実際の端子を選択**してください。
   必要なら「モニター出力」に別のヘッドホン等を選択します。使わない場合は「なし」のままにします。
3. WAV、MP3、FLAC、M4Aなどの音声ファイルを選びます。ウィンドウへの**ファイル1個のドラッグ＆ドロップ**でも選択できます。フォルダー・複数ファイルは対象外で、測定中の差し替えはできません。選択だけでは再生しません。
4. 速度（0.5～4倍）、出力ゲイン（初期値 −18 dB）、測定範囲を設定します。**「全部」（初期値ON）はファイル末尾まで**測定します。OFFにすると秒数（1～86400秒、初期値15秒）を指定できます。再生速度に合わせて周波数も変わります（2倍速なら周波数も2倍）。音程維持は行いません。
5. 「再生して測定」を押します。「全部」は先頭から末尾まで、それ以外は**速度変換後の指定秒数まで**再生します。短いファイルは末尾で終わります。
6. 録音後、自動比較結果と最大ピーク付近の**出力・入力の2段の波形**が表示されます。「位置」と「表示幅」は上下で連動します。
7. 「WAV・結果を保存」で録音と、設定・数値・比較結果を含む `録音名.wav.txt` を保存します。

録音は48 kHz / 16 bit / モノラル、出力は48 kHz / 16 bit / ステレオです。録音を開始して約0.3秒後に再生し、終了後約0.5秒まで録音します。対応しない入出力デバイスはエラーになります。録音音声は出力へ戻しません。

### 一時停止とモニター出力

- 録音・再生中に「一時停止」を押すと、測定出力・モニター出力・録音が停止し、ボタンが「再開」に変わります。再開すると続きから処理します。一時停止中も「停止」で終了できます。音声準備中・比較中は一時停止できません。
- 停止中の時間は測定経過時間と録音に含めません。ただし、入出力機器の停止・再開はサンプル単位で同期できず、境界には欠落や余分な音が生じ得ます。そのため**一時停止した測定は自動相似度比較を省略**します。波形・ピーク確認・WAV保存は可能で、一時停止回数を結果に記録します。音飛びを検査するときは途中で一時停止せず測定してください。
- モニター出力には、速度変換・出力ゲイン適用後の同じ再生データを送ります。その上でモニター専用音量を適用します。MIC INの返し音ではありません。録音された音や実際のLINE OUTの異常を、そのまま聴ける機能ではありません。
- 測定用と同じ出力先は指定できません。各機器の遅延・クロックが異なるため、2つの出力の完全同期は保証しません。測定出力を基準に終了し、モニターも停止します。
- モニター先が開けない場合は測定を開始せずエラーを表示します。第2出力の有無・デバイス名も設定に保存し、古い設定ファイルでは「なし」になります。

モニター音量は測定中も変更できます。[waveOutSetVolume](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/nf-mmeapi-waveoutsetvolume) にモニターのハンドルを指定し、その出力だけに適用します。音量制御に非対応のデバイスではエラーになります。その場合はモニターを「なし」にするか別のデバイスを選んでください。

一時停止・再開には [WindowsのwaveOutPause / waveOutRestart](https://learn.microsoft.com/en-us/windows/win32/multimedia/stopping-pausing-and-restarting-playback) を使用しています。ドライバーにより停止までに遅延が生じる場合があります。

「全部」の場合も測定は実時間で行います（例：30分の音声を2倍速なら約15分）。波形位置の上限は変換後の長さに合わせて広がります。現在は音声・録音・比較用データをメモリに保持するため、長い音源には十分な空きメモリが必要です。64 bit版としてビルドし、メモリ不足や変換後PCMが約2 GBを超える場合はエラーを表示します。途中までを全体測定成功として扱うことはありません。準備・測定・比較は「停止」で中断できます。

### 自動ゲイン（デジタルピーク）

「自動ゲイン（−1 dBFS）」をONにすると、再生前にWAV全体を解析し、最大振幅を−1 dBFS以下に近づけます。左右で大きい方のピークを使って両チャンネルへ同じ倍率をかけるため、左右の音量比と波形の形を保ちます。ゲインは上限側へ丸めない0.1 dB単位で、適用値を画面と測定ログに表示します。元のWAVは変更しません。

- 「再生のみ」は100%固定の波形、「再生して測定」は指定速度へ変換した波形から計算します。部分再生でも全体のピークを使うため、準備時はファイル全体を読み込みます。
- ONの間は手動ゲインを使用しません。OFFへ戻すと前の手動値を使います。ON/OFFは次回起動時にも復元します。
- 無音は0 dBのままです。元からあるピークカットや歪みは復元しません。MIC INの上限や実機の最適入力レベルを測定する機能ではなく、アナログ経路でのクリップは別途録音で確認してください。

### 設定の自動保存

変更した設定は `bin\settings.xml` に自動保存し、次回起動時に復元します。保存対象は入出力デバイス名、モニター音量、測定速度、手動ゲイン・自動ゲインON/OFF、全部／秒数、認識機種・エンジンのパス、波形表示幅・出力チャンネル・遅延補正、最後に選択したファイルです。最後のファイルは存在する場合だけ復元し、自動再生はしません。ビルドし直しても設定ファイルは保持します。

デバイスは列挙順ではなく名前で復元します。未接続・名前変更・同名の複数デバイスの場合は未選択とし、再選択が必要です。設定の読み書きに失敗した場合は画面に表示します。設定を初期化するには、終了後に `bin\settings.xml` を削除してください。アプリの設定のみ保存し、Windows側の音量やマイクブーストは変更しません。

### 出力・入力の波形表示

- 上段のオレンジ色は速度変換・ゲイン適用後の再生用PCM、下段の緑色はMIC INの録音です。出力は端子の電圧を実測した波形ではありません。
- 出力の「左」「右」「左右平均」を切り替えられます。自動比較後は、比較に使ったチャンネルが選ばれます。
- 遅延が求まった場合は「遅延を合わせる」が使えます。初期状態では有効で、同じ横位置に対応する出力と入力を描きます。表示には基準区間の一定の遅延を使い、区間ごとの微小な遅延変化までは補正しません。
- 「位置」は録音時刻です。各段にそれぞれのデータの時刻を表示します。比較結果の再生時刻に遅延を加えると、その箇所を探せます。データ範囲外は空白です。
- 遅延未確定・補正OFFの場合は「未整列」と表示し、出力・入力それぞれの先頭を0秒として描きます。
- 振幅の目盛りは上下とも±1.0が0 dBFSです。見た目の音量・極性の補正は行わず、実データの大きさを表示します。波形は出力データの準備後と録音終了後に表示し、リアルタイムの入力表示ではありません。

## ピーク検査

- 最大ピーク・録音全体のRMSをdBFSで表示します。メーターは測定中の最大ピークを保持します。
- 「上限付近」は −0.1 dBFS以上のサンプル数です。
- 「レール付近」は16 bit値の絶対値32760以上のサンプル数です。
- 「平坦部」は、振幅が0.1以上で、同符号の隣接差が2 LSB以下のサンプルが5個以上続く区間数です。低周波の波形や元音源でも検出されるため、参考判定です。
- 最大ピークが −60 dBFS未満の場合は入力不足として表示します。

## 再生データとの自動比較

比較する基準は、元ファイルそのものではなく、**速度・出力ゲインを適用した、実際に再生へ送ったPCMデータ**です。

1. 左・右・左右平均のうち、モノラル録音に最も相関する信号を選びます。
2. 最大2秒の遅延、音量差、極性反転を補正します。十分な相関がない場合は「比較不能」とします。
3. 0.5秒ごとに相関・相対誤差・音量の変化を調べ、さらに10 ms単位で短い音抜け・クリック等の波形差を調べます。
4. 差が大きい区間を時刻付きで表示します。**比較結果の時刻は再生開始を0秒**としています。録音波形で探すときは、結果に表示された遅延を加えてください。

### 波形の相似性チェック

0.5秒ごとの有音区間を**全サンプル**で比較し、相似度の平均・最低値・区間別スコアを表示・保存します。平均は比較したサンプル数による加重平均です。末尾の0.5秒未満の区間も対象です（4サンプル未満は除外）。

相似度は、時間を合わせ、音量差とDCオフセット（波形の上下位置）を除いたPearson相関に、基準区間で求めた全体の極性を適用した値です。0～100%で表示します。全体の極性反転は許容しますが、一部区間だけの反転は相似度を下げます。録音が無音になった有音区間の相似度は0%です。

**95%未満は「要確認」**として区間時刻を表示します。この閾値は本ツールの初期の目安で、品質規格や「正常である確率」を意味しません。元音声がほぼ無音の区間は相似度の集計から除外し、対応付けができない録音は相似度を表示せず「比較不能」とします。音抜け・ピーク・短時間の波形差の検査も並行して行うため、平均相似度が高くても要確認になる場合があります。

時間合わせ用の基準区間が破損して十分な相関が得られない場合は、先頭・末尾の区間でも時間合わせを試みます。相似度が下がる原因には機器やケーブル以外に音声補正・周波数特性・雑音も含まれます。

主な判定値は、基準相関0.6以上、区間の相対誤差35%超、10 msの相対誤差50%超、音量比0.5未満・2超、区間間の遅延変化2 ms超です。相対誤差は音量を合わせた後の誤差で、0.5秒の値はDC成分も除いた相関から算出します。基準信号が小さい区間は通常の比較から除外し、ほぼ無音の区間に −40 dBFS超のRMS入力があれば別途表示します。時刻検出・閾値ともに簡易的な診断です。

**「破損なし」を保証するツールではありません。** アナログ経路では周波数特性・位相・雑音で波形が変わります。マイクブースト、AGC、ノイズ抑制、音声補正でも差が生じます。ピーク上限未満の歪み、軽微な変化、単一トーン等の周期的な音声では、正しく判別できないことがあります。片側のみを録音する接続では、録音していないもう片方のチャンネルの健全性は確認できません。Windows設定は本ツールから変更しません。

判定が出たら、同じ音源を低い出力で再測定し、差が減るか確認すると切り分けに役立ちます。元音源自体にある歪みや、どの機器で歪んだかは確定できません。欠落の可能性が表示された録音・中断された測定では、正常判定として扱わないでください。

## テープデータの認識検査

「データ認識」で対象機種を選び、既存の `DumpListEditor.exe` を「エンジン選択」で指定します。このPCの既知の設置場所は自動検出します。実行ファイルは同梱・コピーしません。初期設定は「認識検査なし」です。

- 新規測定では、元音源・速度変換後の再生データ・録音をそれぞれ復調し、認識ファイル数、復元バイト数、ビット／バイトエラーと、3通りのバイト列比較を表示します。通常の「WAV・結果を保存」に認識結果も含めます。
- 「保存WAVを認識検査」では、画面で選んだ元音源と、ダイアログで選んだ録音を検査します。録音の隣にある `.wav.txt` から旧測定条件を読み取ります。ログがなければ現在の速度・ゲイン・測定範囲を使います。旧ログの音程維持設定は、この過去録音の再現時だけ使用します。音声は再生しません。
- 倍速では認識側の入力周波数設定も速度に合わせます。「波形」の出力チャンネルを基準にモノラルへ変換します。「全部」で測定してください。途中までの測定は元音源全体との一致を確認できません。一時停止・中断した測定の自動認識検査は省略します。
- 対象は PC-6001、PC-6601SR、PC-8001／mkII／mkIISR、PC-8801／mkIISR、MZ-80K／80B／700／1500、X1、MSX、ぴゅう太、FM-7、PASOPIA7、FP-1100、BML3／BML3_IR の19設定です。

DumpListEditor 0.84 の復調処理を別プロセスで呼び、厳しい検査設定・自動修復なしで調べます。バイト列が一致してもエラー情報がある場合は要確認とし、認識ゼロ件同士を成功扱いしません。結果にはエンジンのハッシュと詳細ログを残します。別バージョンの内部API互換性は未確認です。

これは復調できたデータの比較であり、実機でのロード・起動を保証するものではありません。元音源そのものを認識できない場合も区別して表示します。PC-6001の実音源では通常再生と周波数も2倍にした再生の41,082バイト一致を確認しました。他の機種は無音の誤認識検査までで、実音源による網羅検証は未実施です。

## 検証・構成

- `build.ps1`: ビルド
- `test.ps1`: 合成波形を使った検出・比較とFFmpegの速度変換テスト（実音の再生・録音なし）
- `audio-engine-tests.ps1` / `AudioEngineTests.cs`: WinMMを模擬した再生専用・一時停止・リアルタイム音量・終了処理テスト（`test.ps1`からも実行）
- `ui-smoke.ps1`: 画面生成とデバイス列挙、画面画像の生成（実音の再生・録音なし）
- `RecordingLevelChecker.cs`: Windows画面・録音再生・ピーク分析
- `SignalComparison.cs`: 波形の時間合わせと比較
- `TapeRecognition.cs`: 外部復調エンジンの実行とデータ一致検査

実装はWindows標準のWinMMを使用します。バッファーの準備・回収は [Microsoftの仕様](https://learn.microsoft.com/en-us/windows/win32/multimedia/audio-data-blocks) に従っています。自動テストでは実機の再生・録音を行いません。ユーザーによる実機のロード確認結果は「実機での動作確認・既知の問題」に記載しています。
